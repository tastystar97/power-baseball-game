# 마지막 여름 — UI 기획안

상태: 사용자 검토 전 제안. 구현은 시작하지 않았다. 게임 규칙과 수치는 [상세 기획 초안](2026-09-30-highschool-baseball-design.md), [활동표 예시](2026-09-30-activity-examples.md), [개발 계획](../../../tesk.md)을 따르며, 이 문서는 그 내용을 화면으로 옮기는 방법만 다룬다.

예시 화면: [prototypes/ui-screens/index.html](../../../prototypes/ui-screens/index.html). 브라우저에서 파일을 직접 열어 확인하는 정적 시안이다. 표시된 이름·수치·대사는 임시 값이며, 활동 수치는 활동표 예시를 따른다.

범위 변경: 현재 개발은 야구 육성·경기 우선이며 미연시는 보류한다. 호감도와 연애 장면은 이 기획안과 예시 화면에 넣지 않는다.

## 1. 전제

확정된 요구 중 화면 설계에 직접 영향을 주는 것은 다음과 같다.

- 선택형 경기. 한 번의 선택은 공 하나가 아닌 **타자 한 명과의 승부**를 판정한다.
- 첫 시제품은 입학 첫 달(1학년 3월, 4주)이다.
- 선수 생성 때 타자 또는 투수를 고른다. 학교생활·주말·관계는 공유하고 능력·평일 훈련·경기 작전·기록은 역할별로 다르다.
- 매주 평일 활동과 주말 활동을 따로 고른다. 월초에 네 주를 미리 짜지 않는다.
- 주말은 휴식·혼자 외출·개인 연습·자습·동료 교류로 구성한다. 반 친구와 학생 매니저의 미연시 화면은 후속 범위로 보류한다.
- **주간·월말 결산 화면을 매번 보여주지 않는다.** 변화와 기록은 언제든 여는 **상태창**에서 확인한다. (사용자 요청)
- 화면에는 **포트레이트와 배경 그림**이 들어갈 자리를 둔다. (사용자 요청)

주말 슬롯 수, 경기 배치(토요일 경기 후 일요일 자유 활동), 관계 단계, 배경, 능력 구성, 색상, 에셋 규격, 기술 구성은 아직 제안이다.

## 2. 설계 원칙

1. **지금 할 일을 가장 먼저 보여준다.** 한 화면에는 주요 행동 하나를 둔다. 작은 화면에서도 선택지가 첫 화면에 최대한 보이게 한다.
2. **흐름을 멈추는 정리 화면을 만들지 않는다.** 한 주가 끝나면 바로 다음 주 평일로 넘어가고, 지난 주 변화는 한 줄로만 알린다. 자세한 내용은 상태창에서 원할 때 본다.
3. **선택 전에는 전망, 선택 후에는 이유를 보여준다.** 활동은 성장·체력·스트레스 변화를, 경기 작전은 ‘불리·보통·유리’와 한 문장 이유를 먼저 보여준다. 결과는 실제 변화와 주요 보정 요인을 보여준다.
4. **할 수 없는 선택은 숨기지 않고 비활성화한다.** 버튼 가까이에 이유를 적는다. 예: “2사라 희생번트를 할 수 없습니다.”, “이번 주말에는 가족 행사로 만날 수 없습니다.”
5. **색만으로 상태를 전하지 않는다.** 증감은 `▲3`, `▼5`처럼 기호와 숫자를, 위험은 ‘주의’ 같은 글자를 함께 쓴다.
6. **상태창과 보조 정보는 진행을 바꾸지 않는다.** 열고 닫아도 진행 단계와 저장 상태가 바뀌지 않는다.
7. **역할 차이는 같은 틀 안에서 내용만 바꾼다.** 타자와 투수의 화면 배치는 같고, 능력 이름·평일 활동·작전·기록 항목만 다르다.
8. **야구부 관계는 간결하게 보여준다.** 감독 평가와 동료·라이벌의 반응, 친밀도 변화를 보여준다. 연애 호감도와 교제 상태는 현재 UI에 넣지 않는다.
9. **그림이 없어도 화면이 완성되어 있어야 한다.** 모든 그림 자리는 그림이 없을 때 대신 보일 모양을 정해 둔다. 정보를 그림에만 담지 않는다.

### 색

| 남색 | 본문 글자, 주요 버튼 | `#1f2d4d` |
| 크림 | 전체 배경 | `#f7f1e1` |
| 종이 | 패널·카드 배경 | `#fffaf0` |
| 운동장 초록 | 성장, 긍정 변화, 야구장 잔디 | `#4f8f4a` |
| 흙색 | 야구장 내야 | `#c79a63` |
| 금색 | 현재 선택·현재 단계, 주인공 표시 | `#c98a12` |
| 경고 주황 | 위험, 대가, 부정 변화 | `#b4441f` |

| 전광판 | 경기 화면 점수판 배경 | `#1c2a22` |

평일은 밝은 종이 느낌, 경기는 어두운 전광판과 야구장, 주말은 노을빛 배경으로 구분해 지금이 어느 단계인지 한눈에 알게 한다. 색 값은 시안의 임시 값이며 플레이하면서 조정한다.

### 글자와 크기

- 한국어 가독성을 우선해 시스템 한글 글꼴을 쓴다. 웹 글꼴 도입은 이후 결정한다.
- 본문 16px, 보조 설명 14px 이상. 숫자는 폭이 같은 숫자(`tabular-nums`)로 맞춘다.
- 버튼과 선택 카드는 높이 44px 이상. 키보드 포커스는 3px 주황 테두리로 분명하게 표시한다.

### 공통 요소

| 패널 | 종이색 배경과 옅은 테두리. 화면의 구역을 나눈다. |
| 주요 버튼 | 남색 채움. 화면마다 하나만 둔다. |
| 선택 카드 | 활동·사건 선택지·경기 작전·대화 선택지. 제목, 효과 칩, 한 줄 설명으로 구성한다. |

| 이번 주 진행 막대 | `평일 → 학교 사건 → 경기 → 주말`. 지나간 단계 ✓, 현재 단계 강조, 없는 단계는 ‘없음’. |
| 지난 주 한 줄 | 새 주 평일 화면 위에 지난 주의 주요 변화를 한 줄로 적고 ‘상태창에서 보기’ 링크를 둔다. |
| 안내·주의 목록 | 선택 전 위험과 참고 사항. ‘주의’, ‘안내’ 글자로 구분한다. |
| 수치 막대 | 체력·스트레스·투구 부담. 막대 옆에 항상 숫자를 적는다. |
| 배경 배너 | 평일·사건·주말 화면 맨 위의 가로로 긴 배경 그림. 장소와 시간대를 알린다. |
| 포트레이트 | 인물의 허리 위 그림. 사건·교류 장면·상태창에 쓴다. |
| 얼굴 아이콘 | 원형으로 자른 인물 얼굴. 관계 목록·교류 상대 고르기·경기 응원에 쓴다. |
| 장면 무대 | 배경 위에 포트레이트를 세우고, 대사는 그 아래 카드에 둔다. |
| 상태창 버튼 | 상단 줄 오른쪽. 게임 진행 중 모든 화면에 있다. |
| 저장 표시 | 상단에 ‘자동 저장됨’ 또는 ‘저장되지 않음’. |

## 4. 화면 배치

### 데스크톱 (너비 960px 이상)

```text
┌──────────────────────────────────────────────────────────────────┐
│ 마지막 여름 │ 1학년 3월 4주차 · 평일 │ 타자 · 김야구 │ 자동 저장됨 [상태창] │
├──────────────┬──────────────────────────────┬────────────────────┤
│ [포트레이트]  │ ┌ 배경 배너 ───────────────┐ │ 관계 (얼굴 아이콘)  │
│ 김야구        │ └──────────────────────────┘ │                    │
│ 체력·스트레스 │ 진행 막대 · 지난 주 한 줄      │ 이번 달             │
│ [상태창 열기] │ 현재 화면 · [주요 버튼]        │ (예정·지난 주)      │
└──────────────┴──────────────────────────────┴────────────────────┘
```

- 가운데 영역이 가장 넓고, 주요 버튼은 그 안에 둔다.
- 경기 화면과 동료 교류 장면은 좌우 영역을 숨기고 장면에 집중한다.
- 시작, 선수 생성, 졸업 화면은 좌우 영역 없이 가운데 한 칸만 쓴다.
- 월간 일정은 별도 진행 화면이 아니라 오른쪽의 ‘이번 달’ 패널과 상태창 ‘일지’다.

### 태블릿·모바일 (너비 760px 미만)

- 상단 줄에는 날짜와 ‘상태창’ 버튼만 남긴다. 좌우 영역은 숨기고, 그 내용은 상태창에서 본다.
- 배경 배너는 조금 더 높게(16:6) 보여준다.
- 경기 화면은 전광판을 합계만 남기고, 작은 내야 그림을 그 옆에 둔다. 작전 선택을 최대한 첫 화면 안에 보이게 한다.
- 상태창은 전체 화면으로 연다.
- 가로 스크롤이 없어야 하며, 긴 한국어 문구는 줄바꿈한다.

## 5. 화면 흐름

```text
시작 ─┬─ 이어서 하기 ─────────────────────────────┐
      └─ 새 게임 → 선수 생성(이름·타자/투수) ─────┤
                                                  ▼
  ┌─▶ 평일 활동 선택 → 평일 결과 ─(학교 사건)─▶ 사건
  │                        │◀─────────────────────┘
  │                        ▼ (경기 있는 주)
  │                  토요일 경기: 승부 선택 ⇄ 승부 결과 (최대 3회)
  │                        ▼
  │                 주말 활동 선택 ─(동료 교류)─▶ 짧은 야구부 대화
  │                        │◀──────────────────────┘
  │                        ▼
  └──── 다음 주 평일 (4주차 뒤에는 새 달 안내 한 줄과 함께) ──── … ──▶ 졸업

  상태창: 진행 중 어느 화면에서든 열고 닫는다. 진행은 바뀌지 않는다.
```

- 주간 결산과 월말 결산 화면은 없다. 주말이 끝나면 바로 다음 주 평일 화면으로 간다.
- 다음 주 평일 화면 위에 지난 주 한 줄을 보여준다. 새 달이 시작되면 “4월이 시작됐습니다 · 이달 예정: …”을 함께 보여준다.
- 없는 사건과 경기는 건너뛰고, 진행 막대에 ‘없음’으로 표시한다.
- 경기가 끝나도 그 주의 주말은 건너뛰지 않는다. 4주차에 경기가 있어도 주말을 거쳐 다음 달로 간다.
- 사건 대화가 끝나면 사건이 생긴 단계의 바로 다음 단계로 돌아간다.
- 첫 시제품은 3월 4주차 주말이 끝나면 “시제품은 여기까지입니다”를 알리고, 상태창에서 3월을 돌아볼 수 있게 한다.

## 6. 화면별 명세

각 화면의 **주요 행동**이 그 화면에 하나뿐인 주요 버튼이다. 그림 자리의 크기와 규격은 7장을 따른다.

### 6.1 시작

- 배경: 학교 정문 그림 위에 제목을 얹는다.
- 표시: 제목, 짧은 소개, 저장 요약(역할·이름·주차·단계·마지막 저장 시각).
- 주요 행동: 저장이 있으면 ‘이어서 하기’, 없으면 ‘새 게임’.
- 새 게임이 기존 저장을 덮어쓸 때는 화면 안에서 확인을 받는다.
- 오류 상태
  - 저장이 손상됐거나 지원하지 않는 버전이면 이유를 알리고 ‘이어서 하기’를 비활성화한다. 저장을 조용히 지우지 않는다.
  - 브라우저 저장소를 쓸 수 없으면 ‘이번 플레이는 저장되지 않습니다’를 알리고 새 게임은 허용한다.

### 6.2 선수 생성

- 입력: 이름(1~8자, 앞뒤 공백 제외), 역할(타자·투수 카드 중 하나).
- 역할 카드에는 주인공 포트레이트(역할별), 능력 6종, 경기에서 고르는 작전, 기록 항목을 보여준다.
- 역할은 이후 바꿀 수 없다는 점을 적는다. 이도류와 도중 전환은 별도 검토 사항이다.
- 주요 행동: ‘입학하기’. 이름이 비었거나 역할을 고르지 않았으면 비활성화하고 이유를 표시한다.

### 6.3 평일 활동 선택

- 배경 배너: 학교 운동장(평일).
- 표시: 이번 주 진행 막대, 지난 주 한 줄, 이번 주 예정(예: “토요일 연습경기”), 현재 체력·스트레스, 평일 활동 카드.
- 활동 카드는 역할에 따라 다르다. 타자 6종, 투수 7종이며 전술 공부·학교 공부·휴식은 공통 카드다.
- 카드를 누르면 선택 상태가 되고, 아래의 ‘선택 전 확인’에 예상 변화와 주의 사항을 보여준다. 예: “토요일 경기 전 체력이 45 아래로 떨어집니다.”
- 주요 행동: ‘이번 주 시작’. 활동을 고르기 전에는 비활성화한다. 누른 뒤에는 이번 주 평일 선택을 바꿀 수 없다.

### 6.4 평일 결과와 학교 사건

- 배경 배너: 사건 장소(예: 타자는 타격 연습장, 투수는 불펜).
- 평일 결과는 한 줄로 보여준다.
- 학교 사건이 생기면 진행을 멈추고 사건 카드를 띄운다. 등장인물 포트레이트(중간 크기), 상황 글, 선택지 2~3개로 구성한다.
- 선택지에는 확정된 효과가 아닌 예상 방향만 적는다. 예: “라이벌과의 관계가 달라질 수 있다.”
- 선택 후 실제 변화를 보여주고 다음 단계(경기 또는 주말)로 가는 버튼을 보여준다. 한 번 고른 선택지는 다시 누를 수 없다.
- 역할별로 대사와 야구 보상이 다르다. 투수에게 타격 보상을 주지 않는다.

### 6.5 경기 — 승부 선택

전광판·야구장·상대 정보·작전 선택으로 구성한다. 경기 화면은 배경 그림 대신 SVG 야구장을 쓴다.

- 전광판: 두 팀의 이닝별 점수, 현재 이닝(초·말), 아웃 수, 주자 상황. **볼·스트라이크는 표시하지 않는다.** 선택 단위가 공 하나가 아니기 때문이다.
- 야구장: 베이스와 주자를 보여준다. 주인공이 타석·주자·마운드에 있으면 금색 ‘나’ 표시로 구분한다.
- 상대 정보: 타자 주인공은 상대 투수, 투수 주인공은 상대 타자의 특징 2~3개.
- 내 상태: 체력(공통). 투수는 **투구 부담** 막대와 교체 기준을 함께 보여준다.
- 작전 카드: 역할별 4종. 카드마다 ‘유리·보통·불리’와 한 문장 이유를 적는다. 투수 카드에는 예상 투구 부담도 적는다.
  - 타자: 정확하게 맞히기, 장타 노리기, 공 골라내기, 희생번트
  - 투수: 직구로 승부, 변화구로 유도, 맞혀 잡기, 유인구 위주
- 희생번트는 2사이거나 진루할 주자가 없으면 비활성화하고 이유를 적는다.
- 몇 번째 중요 장면인지 표시한다. 예: “중요 승부 2/3”.
- 동료의 응원이나 신호가 있으면 얼굴 아이콘과 함께 한 줄로 보여준다. 응원 효과가 있다면 판정 이유에도 적는다.
- 작전 카드를 누르면 곧바로 판정한다. 판정 중에는 모든 카드를 잠가 중복 판정을 막는다.

### 6.6 경기 — 승부 결과

- 결과 이름(예: 우중간 안타, 삼진, 볼넷)과 선택한 작전.
- 야구장에 타구 방향과 주자 이동을 화살표로 보여준다. 글로도 “2루 주자 득점, 1루 주자 3루로”처럼 적는다.
- 판정 이유: 주요 보정 요인 2~4개. 예: “컨택 E — 보통”, “상대 제구 불안 — 유리”.
- 바뀐 점수·아웃과 이번 경기 개인 기록.
- 투수는 투구 부담 변화를 보여주고, 한계에 도달하면 교체 안내 후 남은 경기를 요약한다.
- 주요 행동: ‘경기 계속’. 요약 구간을 거쳐 다음 중요 장면 또는 경기 종료로 가며, 경기 종료 후에는 주말 활동으로 간다. 경기 전체 기록은 상태창 ‘기록’에 쌓인다.

### 6.7 주말 활동 선택

- 배경 배너: 동네 거리(일요일). 화면 전체도 노을빛으로 바꿔 주말임을 알린다. 경기 주에는 “토요일 경기를 마친 일요일”처럼 적는다.
- 표시: 경기 결과 한 줄, 현재 체력·스트레스, 주말 활동 5종.
  - 휴식, 혼자 외출, 개인 연습, 자습, 동료 교류
- ‘동료 교류’를 고르면 함께할 동료를 얼굴 아이콘·장소·관계 단계와 함께 펼친다. 데이트 장소 선택이나 연애 사건 목록은 만들지 않는다.
- 함께할 수 없는 동료는 비활성화하고 이유를 적는다. 휴식·혼자 외출로 주말을 마칠 수 있다.
- 주요 행동: ‘주말 보내기’. 선택하기 전에는 비활성화한다.

### 6.8 짧은 동료 교류

- 장면 무대: 교류 장소의 배경(16:9) 위에 동료의 포트레이트를 세운다. 장소·시간은 무대 왼쪽 위에 적는다.
- 대사는 무대 아래 카드에 둔다. 그림 위에 글을 겹치지 않아 어떤 그림이 와도 읽기 쉽다.
- 선택지는 2~3개. 결과로 상대의 반응 대사와 변화를 보여주고, 반응에 맞춰 포트레이트 표정을 바꾼다(기본·웃음).
- 활동의 기본 효과(예: 캐치볼의 수비 +1, 친밀도 +3)는 대답과 관계없이 같고, 대답은 반응 대사와 작은 추가 효과만 바꾼다.
- 관계 변화는 동료 친밀도의 변화와 이유로 알린다. 연애 호감도·교제 단계는 표시하지 않는다.
- 별도 긴 개인 시나리오를 첫 달의 필수 조건으로 두지 않는다.
- 주요 행동: ‘주말 마치기’ → 다음 주 평일.

### 6.9 졸업

- 주인공 포트레이트와 결정된 진로, 그 이유(역할별 능력, 경기 기록, 학업).
- 역할별 통산 기록, 기억에 남는 선택.
- 야구 진로와 함께 감독·동료·라이벌과의 추억을 얼굴 아이콘과 함께 짧게 보여준다. 연애별 후일담은 보류한다.
- 원하던 진로가 아니어도 완결된 결말로 서술한다.
- 졸업은 3년에 한 번 보는 마무리 장면이므로 결산처럼 자세히 보여준다.
- 주요 행동: ‘새 회차 시작’. 기존 저장을 덮어쓰면 확인을 받는다.

### 6.10 상태창

주간·월말 결산을 대신하는 화면이다. 진행 중 어느 화면에서든 상단 ‘상태창’ 버튼으로 연다.

- 형태: 현재 화면 위에 뜨는 창. 모바일에서는 전체 화면. `Esc` 또는 ‘닫기’로 닫으면 연 버튼으로 포커스가 돌아간다. 열려 있는 동안 키보드 포커스는 창 안에서만 돈다.
- 왼쪽(모바일은 위): 주인공 포트레이트, 이름, 역할, 학년·주차, 체력·스트레스.
- 항목 탭
  - **능력:** 역할별 능력 6종(등급·수치·막대), 생활 상태 4종, 특수능력과 다음 목표 힌트.
  - **변화:** ‘이번 주 / 이번 달’ 전환. 항목마다 시작 값 → 지금 값, 변화량, 원인(예: “평일 −20 · 사건 −4 · 경기 −2 · 주말 −8”).
  - **기록:** 역할별 시즌 기록과 경기별 결과, 감독 평가.
  - **관계:** 감독·라이벌·동료 포수의 포트레이트, 관계 단계, 친밀도, 최근 사건. 보류된 호감 상대의 빈 패널은 만들지 않는다.
  - **일지:** 주별 평일·주말 활동, 기억에 남는 선택.
- 열고 닫아도 진행 단계와 저장 상태는 바뀌지 않는다. 경기와 교류 장면 중에도 열 수 있지만 읽기만 할 수 있다.
- 지난 주 한 줄의 ‘상태창에서 보기’는 ‘변화 → 이번 주’를 연다.

## 7. 그림 자리

### 7.1 종류와 규격

| 종류 | 원본 비율·권장 크기 | 형식 | 쓰이는 곳 |
| --- | --- | --- | --- |
| 배경 | 16:9 · 1600×900 이상 | JPG 또는 WebP | 시작 화면, 평일·사건·주말 배너, 교류 장면 무대 |
| 포트레이트 | 3:4 · 900×1200 이상 | 투명 배경 PNG 또는 WebP | 선수 생성, 사건, 교류 장면, 상태창, 졸업 |
| 얼굴 아이콘 | 1:1 · 256×256 | PNG 또는 WebP | 관계 목록, 교류 상대 고르기, 경기 응원, 졸업 추억 |

- **배경 배너**는 16:9 원본의 가운데 가로 띠(데스크톱 16:5, 모바일 16:6)만 보여준다. 장소를 알아볼 요소는 세로 가운데 1/3 안에 둔다.
- **포트레이트**는 허리 위 구도로, 인물 아래쪽을 그림의 아래 가장자리에 맞춘다. 화면은 아래쪽 가운데를 기준으로 맞춘다.
- **표정**: 모든 인물은 ‘기본’이 필수다. 교류 장면에 나오는 동료 포수는 ‘웃음’을 추가하는 안이다. 없는 표정은 ‘기본’으로 대신한다.
- **얼굴 아이콘**은 선택 사항이다. 없으면 기본 포트레이트의 위쪽을 원형으로 잘라 쓰고, 포트레이트도 없으면 이름 첫 글자 원형을 쓴다.
- 그림 안에 글자를 넣지 않는다. 장소 이름·대사 같은 글은 화면이 DOM으로 따로 보여준다.
- 포트레이트와 배경은 장식으로 보고 화면 낭독기에는 읽히지 않게 한다. 인물 이름과 장소는 항상 글로 함께 적는다.

### 7.2 그림이 없을 때

| 자리 | 대신 보일 모양 |
| --- | --- |
| 배경 | 시간대별 색(낮·저녁·실내) 그라데이션에 옅은 사선 무늬. 개발 중에는 “배경 · 장소 이름 · 16:9” 이름표를 단다. |
| 포트레이트 | 점선 틀 안의 사람 실루엣. 개발 중에는 “인물 · 표정” 이름표를 단다. |
| 얼굴 아이콘 | 포트레이트 위쪽을 자른 그림, 그것도 없으면 이름 첫 글자 원형. |

출시 화면에서 이름표를 보일지는 T8에서 정한다.

### 7.3 첫 달에 필요한 그림

- 배경 6장: 학교 정문(봄), 학교 운동장(평일 오후), 타격 연습장, 불펜, 동네 거리(일요일), 하천 둔치(일요일 오후).
- 포트레이트 6장: 주인공 타자·투수, 감독, 라이벌 각 ‘기본’ 1장, 동료 포수 ‘기본·웃음’ 2장.
- 얼굴 아이콘: 선택 사항.

그림은 직접 만들거나 사용 권한이 확인된 것만 쓴다. 그림마다 안정적인 ID, 파일 경로, 만든 사람, 사용 조건을 `content` 영역의 데이터로 기록한다. 보류된 호감 상대의 그림은 미연시를 다시 시작할 때 목록에 추가한다.

### 7.4 시안의 에셋 슬롯 화면

예시 화면의 ‘에셋 슬롯’에서 모든 그림 자리를 규격과 함께 보고, 내 컴퓨터의 이미지를 넣어 각 화면에서 어떻게 보이는지 확인할 수 있다. 넣은 이미지는 그 브라우저 창에서만 보이며 어디에도 올리거나 저장하지 않는다. 이 화면은 시안 도구이며 게임 화면이 아니다.

## 8. 입력과 접근성

- 모든 선택은 `button` 요소로 만들어 마우스·터치·키보드(Tab, Enter, Space)로 조작한다.
- 화면이 바뀌면 새 화면의 제목으로 포커스를 옮긴다.
- 결과·주의 문구처럼 바뀌는 내용은 화면 낭독기가 읽도록 `aria-live`로 알린다.
- 야구장 SVG에는 주자 상황을 글로 담은 설명을 붙이고, 같은 내용을 화면에도 글로 적는다.
- 대화는 한 번에 전부 보여준다. 글자가 한 자씩 나오는 연출을 넣는다면 건너뛰기를 제공하고, 동작 줄이기 설정(`prefers-reduced-motion`)에서는 끈다.
- 동작 줄이기 설정에서는 주자 이동 애니메이션과 표정 전환 효과도 끄고 결과만 보여준다.

## 9. 규칙과 화면의 경계

- 화면은 `game` 영역이 계산한 상태와 판정 결과를 표시만 한다. 전망 등급, 비활성 이유, 예상 변화, 함께할 수 있는 동료 목록, 상태창의 변화 원인도 규칙 쪽에서 계산해 넘긴다.
- 능력 이름, 활동 목록, 작전 목록, 대사, 수치 기준, 그림 ID와 파일 경로는 `content` 영역의 데이터를 읽는다. 화면 코드에 따로 적지 않는다.
- 상태창의 열림과 탭, 고르는 중인 카드 같은 화면 상태는 저장 데이터에 넣지 않는다. 확정된 선택, 진행 중인 사건·경기·대화와 돌아갈 단계, 상태창에 보여줄 변화 기록은 저장한다.
