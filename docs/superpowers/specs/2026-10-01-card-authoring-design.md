# 카드 제작 도구와 가져오기·내보내기 — v0.7 구현 기준

상태: **구현 완료**. [실행 계획](../plans/2026-10-01-card-platform.md)과 [개발 기록](../../development-log.md)을 따른다. 회의 당시 해시 저장·에셋 저장소·추가 메타데이터 제안 대신 아래의 실제 구조를 채택했다.

## 사용자 흐름

1. 별도 `/card-editor/`에서 예시 팩을 열고 카드 생성·복제·삭제, 인물·그림·훈련·스킬·사건을 편집한다.
2. 미완성 초안도 자동 저장한다. 형식이 손상된 초안은 덮어쓰지 않고 오류를 알리며 새 팩 또는 파일 열기로 복구한다.
3. 카드팩 검사로 형식·참조·역할·선행·보상·이미지를 검증한 뒤 현재 카드 또는 전체 팩을 내보낸다. 현재 카드 내보내기는 의존 스킬·사건·이미지를 포함한다.
4. 게임의 카드 라이브러리에서 파일을 미리 보고 등록한다. 등록은 팩 단위 트랜잭션이며 일부만 적용하지 않는다.
5. 새 선수에서 6장을 선택한다. 월별 재선택 없이 덱 전체가 동행·인카운터 후보다. 진행 중인 선수의 정의·그림은 시작 당시 내용으로 고정한다.
6. 게임에서도 선택 카드 또는 전체 팩을 내보내 제작기로 다시 연다. 팩 파일에는 선수·성적·인연 등 플레이 저장이 없다.

## 편집 범위

| 항목 | 현재 구현 |
| --- | --- |
| 팩 | ID, 이름, 개정, 제작자, 소개, 새 팩·파일 열기·초안 저장 |
| 인물 | 이름, 카드 제목, 인물 역할 설명, 소개, 색상, PNG·JPEG·WebP 초상화 |
| 훈련 | 전문 1차 또는 회복, 역할별 선호 1~3개, 동행 회복·스트레스·합동 회복·1차 보너스 |
| 스킬 | 역할별 일반/상위 연결·새 계열 생성, 이름·설명·비용·역할·선행, 야구 능력 조건, 발동 조건·효과 |
| 사건 | 생성·삭제, 일상/성장, 인연·선행 성장, 본문과 두 선택지·응답·능력·체력·스트레스·신뢰·인연·SP·힌트·상위 개방 |
| 미리 보기 | 입학 능력을 기준으로 역할·인연·학습 단계·이닝·아웃·체력·스트레스·주자·승패를 조절하고 실제 훈련·경기 평균을 계산 |

역할별 새 스킬 계열은 일반→상위와 첫/최종 고유 사건 보상을 연결한다. 상위를 해제하면 숨은 사건 보상과 사용하지 않는 정의를 정리한다. 그림은 복제 카드가 같은 에셋을 공유할 수 있지만 교체할 때 새 식별자를 만들어 다른 카드 그림을 바꾸지 않는다. 미완성 카드를 삭제해도 나머지 초안은 유지한다.

상위 미리 보기는 습득 조건을 충족했다고 가정한다. 능력 직접 입력·사건 흐름 재생·목록 정렬/검색·말투/태그 전용 필드·초안 파일 백업·그림 자르기는 구현하지 않았다. 인물 소개와 실제 대사에서 개성을 작성한다.

## 공통 규격

실제 인터페이스는 [schema.ts](../../../src/cards/schema.ts), 참조 검증·ZIP 처리는 [pack.ts](../../../src/cards/pack.ts)다. 외부 도구에는 [규격 문서·JSON Schema·예제](../../cardpacks/README.md)를 제공한다.

- 기본 팩도 외부 팩과 같은 CardPack 규격이다. 기본은 18장·90사건·44스킬이며 [확장 설정](2026-10-01-support-expansion-notes.md)을 따른다.
- 카드팩 형식 `last-summer-cardpack`, 버전 1, 규칙 `summer-7`, 저장 버전 7을 구분한다.
- `.cardpack`은 ZIP이다. `manifest.json`에 팩 정보·이미지 목록, `content.json`에 cards/skills/events, `assets/`에 이미지를 담는다. 외부 URL과 실행 코드는 사용하지 않는다.
- 단일 JSON도 읽을 수 있다. 이때 전체 CardPack과 base64 이미지를 포함하며 파일은 2MiB 이하여야 한다.
- 팩 내부 ID는 고유하며 `/`를 포함하지 않는다. 게임에서 외부 ID를 `packId/localId`로 구분한다. 다른 팩의 정의에 의존하지 않고 필요한 스킬·사건을 포함한다.
- ZIP은 20MiB, 파일 하나는 압축 전 2MiB, 전체 압축 해제는 25MiB, 최대 102파일. 이미지 하나는 2MiB, 합계는 20MiB, 최대 100개다. 큰 팩은 여러 ID로 나누어 배포한다.
- 팩 및 통합 라이브러리에는 카드 100장·스킬 240개·사건 1,000개 한도가 있다. 라이브러리 한도에는 기본 콘텐츠도 포함한다.

## 조건·효과와 실제 게임

- 역할별 동행 훈련과 전문 능력 보너스는 기존 인연·합동·성장 곡선을 사용한다.
- 사건은 덱 포함·인연·선행 성장·완료 이력으로 선택한다. 기본은 일상 2개·고유 3개, 인연 20/40/60이다. 외부 카드의 사건 수·인연은 규격 안에서 변경할 수 있다.
- 각 평일 활동 뒤 75%로 추첨하며 연속 두 슬롯 미발생 뒤 보장한다. 조건을 만족한 고유 사건을 우선하고 인물부터 균등 추첨한다. 전반 사건은 후반, 후반 사건은 평가·경기·주말로 돌아간다. 차준서 성장은 주 1회다.
- 상위 개방 사건은 같은 인물의 성장 사건이고 두 선택지 모두 개방 보상을 준다. 역할에 맞는 카드 힌트·상위만 지급한다.
- 상위 학습에는 고유 개방·선행 일반·중립 컨디션의 파생 능력·SP가 필요하다. 공통 스킬에는 양 역할에서 가능한 능력만 요구한다. 같은 계열은 상위만 발동 후보가 된다.
- 발동 조건은 작전·이닝·아웃·체력·스트레스·주자 유무·승/무/패 상태·상대 유형의 AND다. 역할 조건은 해당 역할에만 적용한다. 모순되는 범위와 불가능한 역할 조건을 거부한다.
- 효과는 결과 확률 이동, 투구 부담 감소, 체력 부족 불이익 완화다. 확률 단일 이동은 최대 8%p, 조건 최대 5개·효과 최대 2개. 실제 발동과 정확한 평균 미리 보기가 같은 계산을 쓴다.
- 습득 스킬은 기존 경기 작전에 자동 적용한다. 별도 구종 선택·실시간 조작·이번 후속 경기 개편은 추가하지 않았다.

## 라이브러리와 진행 저장

IndexedDB `last-summer-v7` 안에 `packs`·`session`·`draft`를 분리한다. 정의와 이미지는 팩 및 진행 콘텐츠에 포함한다. 별도 이미지 저장소·해시 참조·전역 에셋 중복 제거는 사용하지 않는다.

| 가져오기 상태 | 처리 |
| --- | --- |
| 새로운 팩 ID | 전체 검증 후 등록 |
| 같은 ID·개정·내용 | 중복 안내, 변경 없음 |
| 같은 ID·개정·다른 내용 | 충돌, 개정 증가 필요 |
| 같은 ID·더 높은 개정 | 사용자가 갱신 확인 후 교체 |
| 같은 ID·낮은 개정 | 거부 |
| 기본 팩 core | 직접 교체 불가, 제작기에서 다른 ID로 복제 |

내용은 해시 대신 정규화된 데이터의 깊은 비교로 판별한다. 진행 저장은 선택한 덱의 정의·그림·의존 스킬·사건을 보유하므로 라이브러리 수정/삭제 후에도 재개할 수 있다. 새 카드팩은 다음 육성에서 선택한다.

v1~v6 저장은 변환하지 않는다. 구형 localStorage 원문은 감지하며 자동 삭제하지 않는다. 새 선수 입학 전까지 현재 저장을 덮어쓰지 않는다. 저장 오류는 안내하고 가능한 현재 세션 플레이를 유지한다. 클라우드 저장·계정·다중 저장 슬롯은 없다.

## 검증과 제한

양 역할 전체 시즌, 18장 모두의 고유 사건 도달, 후반 사건 저장·중복 방지, 상위 대체, 카드팩 왕복·참조·역할·압축 한도, 라이브러리 원자성·스냅샷·초안 복구를 자동 검증한다. 별도 브라우저에서는 이미지 제작부터 외부 성장 사건·상위 습득·갱신/삭제·재내보내기까지 확인한다. 구체 결과는 개발 기록을 따른다.

초기 수치는 조정 가능한 밸런스다. 기본 카드 원화는 이름 아이콘이며 연애·장기 진로·별도 돌파 훈련은 후속 범위다.
