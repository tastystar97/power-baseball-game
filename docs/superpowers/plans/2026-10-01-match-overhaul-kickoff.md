## 2. 시작 전 확인

- `git status`로 작업 트리가 깨끗한지, 직전 개발 브랜치(`codex/development-loop-intelligence`)가 커밋·푸시됐는지 확인한다. 커밋되지 않은 변경이 있으면 **작업을 시작하지 말고** 사용자에게 알린다.
- 기준 브랜치는 사용자가 지정한 것을 쓴다. 지정이 없으면 직전 개발 브랜치의 최신 커밋에서 `feature/match-overhaul` 브랜치를 만든다.
- 구현 계획은 저장 v7, `match.highlights` 최대 3회, 누적 기반 `candidateScore`를 기준으로 썼다. 직전 세션에서 바뀌었을 수 있으므로 `src/game/types.ts`, `src/game/match.ts`, `src/game/competition.ts`, `src/persistence/save.ts`, `src/ui/MatchScreen.tsx`와 `package.json`의 실행 명령을 다시 읽는다. 다른 점은 구현 계획의 "시작 전 조건"에 기록하고 맞춰서 진행한다.
- 시작 시점에 `npm test`, `npm run typecheck`, `npm run build`를 한 번 실행해 기준 상태를 기록한다.

## 3. 사용자가 확정한 결정

- 경기는 **선택형**을 유지한다. 실시간 타격·투구 조작으로 바꾸지 않는다.
- 경기 전체를 타석 단위로 시뮬레이션하고 야구장 연출로 **보여 주다가**, 중요 순간에 멈춰 작전을 고른다. 경기당 선택 횟수 제한(현재 3회)을 없앤다.
- 한 경기는 **약 3분**이 목표다. 재생 속도는 기본 / ×2 / 다음 선택까지의 세 가지다.
- **타자:** 본인 타석은 모두 선택 지점이다. **8번 2루수**로 시작해 감독 면담 사건으로 6번 → 1번(선두) 또는 3번(중심) → 4번으로 올라간다. 강등은 넣지 않는다.
- **투수:** **중계**로 시작해 감독 면담 사건에서 **선발** 또는 **마무리**를 고른다. 등판 중에는 득점권 주자, 상대 3~5번, 라이벌 타자, 7회 이후 2점 차 이내일 때 멈춘다. 마무리는 모든 타자에서 멈추고, 매 경기 9회에 반드시 등판한다.
- 범위가 커져도 결과 종류(병살·희생플라이·3루타·실책 등), 타구 종류와 방향, 이름이 있는 선수단을 넣는다. **텍스트 위주 화면을 야구장 연출 중심으로 바꾸는 것이 핵심 목표다.**
- 선수단 초안은 승인됐다. 승리 확률 표시는 보류다.

## 4. 작업 방식

- 구현 계획의 작업 1~10을 순서대로 진행한다. 규칙 작업(1~8)은 실패하는 테스트를 먼저 쓰고 구현한다. 테스트는 구현을 그대로 따라 쓰지 말고, 외부에서 관찰할 수 있는 야구 규칙과 회귀 위험을 검증한다.
- 규칙 계산은 `game`, 이름·수치·연출 시간은 `content`, 표시와 재생은 `ui`, 버전·검증은 `persistence`에 둔다. 화면이 확률이나 결과를 다시 계산하지 않는다.
- 난수는 기존 시드 방식으로 재현 가능하게 한다. 미리 보기와 재생은 난수를 소비하지 않는다.
- 그림은 직접 만든 SVG·CSS로 그린다. 다른 야구 게임의 화면·에셋을 복제하지 않는다. 의존성은 추가하지 않는다.
- 설계에 없는 판단이 필요하면 합리적으로 정하고 구현 계획의 "검증 기록"에 근거를 남긴다. 선택형을 바꾸는 일이나 범위를 크게 넓히는 일은 사용자에게 먼저 묻는다.
- 커밋은 기능 브랜치에 작업 단위로 한다. 푸시와 병합은 사용자가 요청할 때만 한다.

## 5. 하지 않을 것

- 미연시, 호감도, 연애 관련 UI나 저장 필드.
- 승리 확률·흐름 게이지, 타순 강등, 주인공의 도루 선택.
- 3~6월 범위를 넘는 일정 확장, 경기와 무관한 리팩터링.
- 다른 브랜치나 다른 세션의 변경을 덮어쓰거나 되돌리는 일.

## 6. 완료 기준

- `npm test`, `npm run typecheck`, `npm run build`가 모두 통과한다.
- 1,000경기 밸런스 테스트가 설계의 목표 범위(득점, 안타, 병살, 홈런, 정지 횟수, 연출 시간)를 만족한다.
- 브라우저에서 다음을 실제로 조작해 확인한다.
  - 타자 시즌: 8번에서 시작해 승격까지.
  - 투수 시즌: 중계 → 선발, 중계 → 마무리 각각.
  - 경기 시간 측정, 재생 도중 새로고침, 모바일 폭, 키보드 조작.
- README, 기획 초안, 경기 개편 설계의 구현 상태와 `package.json` 버전을 갱신한다. 구현 계획의 체크박스와 검증 기록을 채운다.
- 완료 보고에는 다음을 구분해서 적는다.
  - 무엇을 바꿨는지
  - 무엇을 어떻게 검증했는지(실제 명령 결과와 측정한 경기 시간)
  - 남은 제한
  - 검증하지 못한 범위
