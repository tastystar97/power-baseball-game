# 6차 스탯 개편 구현 계획

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 공통 1차 능력과 역할별 숙련이 훈련·선발 경쟁·선택형 경기로 이어지는 새 육성 구조를 구현한다.

**Architecture:** `attributes`와 `proficiency`만 선수의 능력 원본으로 저장한다. `derivedStats`가 기존 경기용 능력 키를 계산하고, NPC의 직접 성장 모델은 유지한다. v6만 지원하며 구형 저장은 안내 후 새 게임을 시작하도록 한다.

**Tech Stack:** 현재 React·TypeScript·Vite·Zod 및 Node 내장 테스트. 의존성 추가 없음.

**Spec:** [스탯 개편](../specs/2026-10-01-stat-overhaul.md)

## 공통 제약과 구현 판단

- 기존 사용자 변경을 보존하며 현재 폴더에서 직접 순차 구현한다. 기존 작업과 섞인 커밋·푸시는 하지 않는다.
- 1차 5종, 역할별 숙련 5종, 기반 60% + 숙련 40%, 0~100. 2차 값은 최종 단계에서 반올림한다.
- 숙련 둔화는 활동 시작 시점의 스트레스 보정 전 기반을 쓴다. 보너스 합산 후 성장 곡선을 한 번 적용한다.
- 스트레스는 유효 멘탈에만 적용한다. 선발·경기는 현재 유효 능력, 스킬 습득은 스트레스 보정 전 능력으로 판단해 일시적 컨디션이 영구 습득 자격을 바꾸지 않게 한다.
- 사건도 예상 성장과 실제 성장에 같은 곡선을 사용한다. 경기 센스 보상은 실제 출전 기록이 있는 경우에만 한 번 지급한다.
- 구형 저장 변환·구규칙 실행은 제거한다. 새 버전의 저장 검증·재개와 새 게임 덮어쓰기 확인은 유지한다.

## 실행 기록

- 2026-10-01: 구현 시작. 사용자 개발 요청에 따라 재승인 없이 위 순서로 진행한다.

- Ruling: 커밋·푸시 없이 기존 작업 브랜치에 변경을 남긴다. 이전 사용자 작업과 이번 구현이 한 작업 트리에 있으므로 임의로 묶어 게시하지 않는다.
- Ruling: 사건 미리보기에도 성장 곡선을 적용해 표시와 지급을 일치시켰다. 숙련 격차는 보정 전 기반, 스킬 습득은 보정 전 야구 능력으로 판단한다. 컨디션으로 학습 효율·습득 자격까지 흔들리지 않게 하는 결정이다.
- Ruling: 투수 준서의 기본 성장 배율만 1.25→1.0으로 조정했다. 기존 주전 탈환 검사에서 투수 0/20이었고 수정 후 1/20이다. 난도의 최종 적정성은 플레이 피드백으로 검토한다.
- 검증: 전체 100/100, 타입·빌드 통과. 120시즌 모든 단계 저장 재개, 120시즌 육성 방침 비교, 독립 리뷰 160시즌/16,800전이 검증. 브라우저 양 역할 완주·상태창·모바일·특훈·구형 저장 안내 확인.
- Final: fixed 실제 기반의 소수 오차가 격차10/20과 .5 반올림을 바꾸는 문제. 실패한 재현 2개를 확인한 뒤 정수 단위 계산으로 수정, 재현 2/2와 전체 100/100 통과.
- Final: 판단 보류 항목 정리 — 최종 경쟁 난도는 초기 밸런스로 공개한다. 브라우저·문서는 직접 검증했다. 도달 불가능한 구형 UI 조건은 호환을 제공하지 않으며 실행 경로가 없어 이번 동작에 영향이 없다.
