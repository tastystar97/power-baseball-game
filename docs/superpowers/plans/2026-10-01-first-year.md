# 1학년 완성 구현 계획

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 1학년 1년(3월~이듬해 2월)을 끝까지 플레이할 수 있게 하고, 2학년으로 이어지는 진급 브리지까지 만든다. 그 과정에서 능력 구조(1차 0~1500, A안 훈련), 캐릭터 메이킹, 캠프·각성, 부상, 경기 결과 보상, 화면 로그, 주사위 연출을 함께 구현한다.

**Architecture:** 능력·훈련 규칙은 `game`, 일정·사건·배경·캠프 데이터는 `content`, 표시는 `ui`, 버전·검증은 `persistence`에 둔다. 날짜는 `학년 + 구간(월·주 또는 캠프 턴)`으로 표현해 2학년 이후를 붙일 때 저장 구조를 다시 바꾸지 않는다. 경기 판정은 2차 능력(0~100)만 읽는다.

**Tech Stack:** 현재 React·TypeScript·Vite·Zod와 Node 내장 테스트(`npm test`, `npm run typecheck`, `npm run build`). 의존성은 추가하지 않는다.

**Spec:** [1학년 완성](../specs/2026-10-01-first-year.md), [캐릭터 메이킹](../specs/2026-10-01-character-making.md), [화면 개편](../specs/2026-10-01-ui-overhaul.md). 참고: [경기 개편](../specs/2026-10-01-match-overhaul.md), [스탯 개편](../specs/2026-10-01-stat-overhaul.md), [시뮬레이터](../sims/).

## 시작 전 조건

- **경기 개편(`feature/match-overhaul`)이 완료·병합된 뒤 시작한다.** 이 계획을 쓴 시점에 그 브랜치는 작업 8까지 커밋되었고 화면 작업(작업 9)이 진행 중이었다. 저장은 v8이다.
- 시작할 때 다음을 다시 읽고, 이 계획과 다른 점을 "검증 기록"에 남긴 뒤 맞춘다.
  - `src/game/types.ts`: 상태 스키마, 단계 목록, `monthSchema`, 16주·6경기 상한
  - `src/game/season.ts`: 일정과 대회
  - `src/game/abilities.ts`, `src/game/support.ts`: 능력과 서포트 보너스
  - `src/cards/schema.ts`: 카드팩 규격, 스킬 `requires`
  - `src/persistence/save.ts`: 저장 버전
  - 경기 개편의 능력 읽기 함수: 경기 판정이 능력을 읽는 단일 함수. 이름은 구현 결과를 확인한다.
- 기준 상태로 `npm test`, `npm run typecheck`, `npm run build` 결과를 기록한다.
- **단계 1의 화면 작업은 사용자가 확정한 디자인 시안(`prototypes/` 아래)을 따른다.** 시안이 확정되지 않았으면 규칙 작업(1.1, 1.2, 1.4)부터 진행하고, 화면 작업(1.3, 1.5, 1.6, 1.7)은 시안 확정 후 진행한다.
- 구형 저장은 테스트베드 정책(구형 호환 제외, 조용히 삭제하지 않고 안내)을 따른다.

## 공통 제약

- 선택형 경기, 연애 기능 보류, 고정 직업 대신 훈련·스킬 조합으로 만드는 스타일(각성은 누적형) 원칙을 지킨다.
- 2차 능력과 숙련, 확률은 화면에 숫자로 보여 주지 않는다. 1차 능력(0~1500)과 종합 능력, 강점·약점 꼬리표, 유리·보통·불리만 보여 준다.
- 주사위는 확정된 결과를 보여 주는 연출이다. 난수를 소비하지 않는다. 새로고침이나 재개 뒤에는 다시 굴리지 않는다. 동작 줄이기 설정에서는 생략한다.
- 수치는 설계 문서의 값을 콘텐츠 상수로 모은다. 같은 값을 UI에 복제하지 않는다.
- 단계마다 플레이 가능한 상태로 끝낸다. 각 단계가 끝나면 버전을 올리고 README와 회의 기록을 갱신한다.
- 커밋은 기능 브랜치에 작업 단위로 한다. 푸시와 병합은 사용자가 요청할 때만 한다.

## 단계 1 — 능력 기반 재구성

### 작업 1.1 — 1차 능력 0~1500과 변환

Files: `src/game/abilities.ts`, `src/game/types.ts`, `src/game/abilities.test.ts`.

Interfaces: `convertPrimary(s): number`(0~100), `baseStats(attributes, stress)`, `derivedStats(s)`, `overall(s): number`.

- [x] 1차 능력 범위를 0~1500 정수로 바꾼다. 변환식은 `100 × (s/1500)^0.46`이다. 기반은 변환값의 가중 평균(기존 공식)이고, 2차 능력은 `기반 × 0.6 + 숙련 × 0.4`(0~100 상한)다.
- [x] 유효 멘탈은 멘탈의 변환값에서 `(스트레스 − 50) × 0.3`을 뺀다. 스킬 발동률의 지능도 변환값을 쓴다.
- [x] 경기 판정이 멘탈을 직접 읽는 곳을 없애고 2차 능력만 쓰게 한다.
- [x] 시작값을 평균 248(파워 230, 지구력 230, 멘탈 260, 지능 290, 센스 230)로 바꾼다. 이 값은 단계 2에서 캐릭터 메이킹 결과로 대체된다.
- [x] 종합 능력은 역할별 2차 능력 5종의 평균이다.
- [x] 숙련은 소수점까지 누적해 0.1 단위 정수로 저장한다.
- [x] 테스트: 변환식의 경계(0, 250, 750, 1500), 2차 능력의 0~100 상한, 스트레스 50/51 경계, 시작 종합 능력이 v0.7 시작 수준과 비슷한지.

### 작업 1.2 — A안 훈련 메뉴와 성장 규칙

Files: `src/content/activities.ts`, `src/game/training.ts`, `src/game/support.ts`, `src/game/engine.ts`, 관련 테스트, 새 `src/content/training-scenes.ts`.

- [x] 평일 메뉴를 파워·지구력·멘탈·지능·센스 훈련과 휴식으로 바꾼다. 수치는 1학년 설계 12절이다. 내부 ID는 새로 정하되, 기존 ID를 참조하는 카드팩(`training` 목록)의 변환 규칙을 함께 정한다.
- [x] 1차 성장 곡선(800/1000/1250에서 ×0.85/×0.6/×0.3), 숙련 곡선(60/70/80/90에서 ×0.4/×0.22/×0.12/×0.06)과 숙련 격차 둔화를 적용한다. 학년 상한 1학년 1000을 적용한다(2학년 1300, 3학년 1500은 상수만 둔다).

- [x] 주말 자율 훈련과 파트너 특훈의 대상 선택을 1차 능력 5종으로 바꾼다. 배율은 이 작업에서 시뮬레이터로 정하고 설계 문서에 기록한다.
- [x] 산책 멘탈 +17, 캐치볼 센스 +8, 훈련 실패 멘탈 −17, 경기 출전 센스 선발 +8·교체 +4로 옮긴다.

- [x] 테스트: 훈련별 1차·숙련 성장, 성장 곡선과 학년 상한 경계, 휴식·실패 시 서포트 보너스 없음, 카드당 보너스 상한, 같은 시드의 같은 배치.
- [x] 검증: [시뮬레이터](../sims/)와 실제 규칙으로 16주 결과를 비교한다. 혼합 방침의 6월 선발 점수가 65 이상(목표 68~69)인지 확인한다.
