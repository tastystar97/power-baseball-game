## 2. 시작 전 확인

- **단계 2가 완료·병합되었는지** 확인한다. 완료되지 않았으면 시작하지 말고 사용자에게 알린다.
- `git status`가 깨끗한지 확인한다. 아니면 시작하지 말고 알린다.
- 기준 브랜치는 사용자가 지정한 것을 쓴다. 지정이 없으면 단계 2가 병합된 최신 커밋에서 `feature/first-year-stage3`을 만든다.
- 16주·6경기에 묶인 코드를 모두 찾아 목록으로 만든다: `monthSchema`, `weekKey`, `schedule`·`records`·`encounterHistory`·`log` 상한, 대회 진행, 차준서 주간 성장, 선발 경쟁 이력. 이 목록을 검증 기록에 남긴다.
- `npm test`, `npm run typecheck`, `npm run build`의 기준 결과를 기록한다.

## 3. 이번 단계의 범위

구현 계획 단계 3의 작업 3.1~3.6이다. 가장 큰 단계라서 **3.1(달력 모델)을 먼저 끝내고 커밋한 뒤** 나머지를 진행한다.

- **3.1** 달력 모델 `학년 + 구간`. 단계 1에서 만든 달력 화면과 주간 달력 띠가 1년 전체(캠프 띠 포함)를 보여 주도록 늘린다. 구간은 주 단위와 캠프 두 종류다. 1학년 달력은 다음과 같다: 3~6월 16주, 7월 4주, 8월 여름 합숙 3턴, 9~11월 12주, 12~1월 동계 캠프 4턴, 2월 4주.
- **3.2** 7월~2월 경기 일정과 대회. 연습경기에는 빠른 진행을 둔다. 11월에 3학년이 은퇴하면서 라인업, 선발 경쟁, 타순·보직 조건을 갱신한다.
- **3.3** 캠프 메뉴와 배율, 캠프 사건, 돌파 시험과 누적 각성(상한 +75, 숙련 둔화 구간 +10, 경기 특성).
- **3.4** 부상. 발생 원인·종류·부위를 구현하고, 선택 전에 위험을 보여 준다. 회복은 기간 경과·휴식·회복 지원 카드로 하며, 영구 손실은 없다.
- **3.5** 경기 결과 보상. 승패, 접전 패배, 우승, 개인 활약, 결정적 순간의 스킬 힌트, 부진과 반성 노트, 라이벌 승리를 다룬다.
- **3.6** 학년별 카드 강도. 수치는 시뮬레이션과 테스트로 정한다.

## 4. 사용자가 확정한 결정 (이번 단계 관련)

- 시즌 중에는 주 단위로 진행하고, 경기 없는 기간은 여름 합숙과 동계 캠프로 압축한다.
- 캠프의 특별 성장은 **누적 각성**이다. 육성 결과가 열어 주는 후보 중에서 고르고, 고정 직업처럼 다른 길을 닫지 않는다.
- 부상은 휴식으로 회복할 수 있다. 영구 손실이나 강제 종료는 없다.
- 경기 결과에 따라 능력·스킬·스트레스를 얻거나 회복한다.
- 3학년 카드가 가장 강하다. 학년별 강도 수치는 **테스트한 뒤 정한다.**
- 1년 플레이 시간 약 1시간 40분을 수용한다. 연습경기 빠른 진행은 그 시간을 줄이는 선택지다.
- 1학년 동안 상대 학교 선수단은 고정한다.

## 5. 작업 방식

- 규칙 작업은 실패하는 테스트를 먼저 쓴다. 특히 구간 전환, 캠프 진입·종료, 경기 후 주말 보존, 사건·보상의 중복 방지, 각 구간에서의 저장·재개를 검증한다.
- 일정·캠프 메뉴·부상 종류·보상 수치는 콘텐츠로 둔다.
- 커밋은 기능 브랜치에 작업 단위로 한다. 푸시와 병합은 사용자가 요청할 때만 한다.

## 6. 하지 않을 것

- 진급 브리지와 덱 갱신(단계 4). 2월 4주 주말이 끝나면 "다음 단계 준비 중" 상태로 멈추게 한다.
- 상대 학교 선수단의 성장과 은퇴, 신입생 카드, 2학년 콘텐츠.
- 연애 관련 기능, 효과음.

## 7. 완료 기준

- `npm test`, `npm run typecheck`, `npm run build`가 통과한다.
- 실제 규칙으로 1년 시뮬레이션을 돌린다.
  - 1학년 끝 1차 평균(목표 약 750)과 종합 능력(목표 약 75)을 측정한다.
  - 방침별 차이, 훈련 실패율, 부상 빈도, 학년별 카드 강도 비교를 측정한다.
  - 목표에서 크게 벗어나면 조정하고 설계 문서에 기록한다.
- 브라우저로 타자·투수 각각 3월부터 2월까지 진행한다.
  - 캠프와 각성, 부상과 회복, 11월 은퇴, 7월 대회 분기, 연습경기 빠른 진행을 확인한다.
  - 1년 플레이 시간을 잰다.
  - 모바일 폭, 키보드, 캠프·부상 도중의 새로고침도 확인한다.
- 저장 버전, README, 1학년 완성 설계의 구현 상태, 구현 계획 체크박스와 검증 기록, `package.json` 버전을 갱신한다.
- 완료 보고에는 다음을 구분해서 적는다.
  - 바꾼 것
  - 검증한 것(측정한 플레이 시간 포함)
  - 남은 제한
  - 검증하지 못한 범위
