## 2. 시작 전 확인

- **경기 개편이 완료·병합되었는지** 확인한다. 끝나지 않았으면 시작하지 말고 사용자에게 알린다.
- `git status`가 깨끗한지 확인한다. 커밋되지 않은 변경이 있으면 시작하지 말고 알린다.
- 기준 브랜치는 사용자가 지정한 것을 쓴다. 지정이 없으면 경기 개편이 병합된 최신 커밋에서 `feature/first-year-stage1`을 만든다.
- 구현 계획의 "시작 전 조건"에 적힌 파일을 다시 읽는다. 다른 점이 있으면 계획의 "검증 기록"에 남기고 맞춘다. 경기 판정이 능력을 읽는 단일 함수의 실제 이름도 확인한다.
- `npm test`, `npm run typecheck`, `npm run build`를 실행해 기준 결과를 기록한다.

## 3. 이번 단계의 범위

구현 계획 단계 1의 작업 1.1~1.6이다.

- **1.1** 1차 능력 0~1500. 변환식 `100 × (s/1500)^0.46`, 2차 능력 0~100 상한, 유효 멘탈과 스킬 발동률은 변환값을 쓴다. 경기가 멘탈을 직접 읽는 곳을 없앤다. 시작값은 평균 248이다.
- **1.2** A안 훈련 메뉴(파워·지구력·멘탈·지능·센스 훈련 + 휴식)와 성장 곡선, 1학년 상한 1000, 서포트 보너스(카드당 최대 +15). 주말 자율 훈련·파트너 특훈 배율은 시뮬레이터로 정해 설계 문서에 기록한다.
- **1.3** 2차 능력과 숙련을 화면에서 숨긴다. 1차 능력, 종합 능력, 강점·약점 꼬리표, 유불리만 보여 준다.
- **1.4** 스킬 습득 조건을 1차·종합 기준으로 옮긴다. 카드팩 규격 버전을 올리고 카드 학년 항목을 추가한다(없으면 2학년).
- **1.5** 화면 로그 패널(데스크톱 오른쪽, 모바일 아래 시트, 분류 탭, "마지막 행동 이후" 구분선).
- **1.6** 경기 주사위를 공용으로 옮겨 훈련 실패와 사건 추첨에도 쓴다.
- **1.7** 게임형 메인 화면(상단 HUD, 장면, 행동 카드, 로그, 하단 메뉴), 주간 달력 띠와 3~6월 달력 화면, 공용 선택 팝업. **사용자가 확정한 디자인 시안(`prototypes/` 아래)을 따른다.** 시안이 확정되지 않았으면 규칙 작업(1.1, 1.2, 1.4)을 먼저 하고 화면 작업은 시안 확정 뒤 한다.

## 4. 사용자가 확정한 결정 (이번 단계 관련)

- 1차 능력만 0~1500이다. 2차 능력은 0~100 상한을 유지한다.
- 플레이어에게는 **1차 능력과 종합 능력만** 숫자로 보여 준다. 2차 능력, 숙련, 확률은 숫자로 보여 주지 않고 대략적인 유불리와 강점·약점 꼬리표로만 전한다.
- 경기 판정은 2차 능력으로만 한다.
- 훈련 메뉴는 1차 능력 5종 훈련과 휴식(A안)이다. 이름은 "(1차 능력) 훈련"이고, 구체적인 연습 장면은 일지에만 쓴다.
- 주사위는 확정된 결과를 보여 주는 연출이고 난수를 소비하지 않는다.
- 게임 화면에 항상 보이는 로그를 둔다. 사용자가 보여 준 예시의 배치 방식만 참고하고 그림이나 문구는 가져오지 않는다.

## 5. 작업 방식

- 규칙 작업은 실패하는 테스트를 먼저 쓴다. 테스트는 외부에서 관찰할 수 있는 규칙과 회귀 위험을 검증한다.
- 수치는 콘텐츠 상수로 모으고 UI에 복제하지 않는다.
- 설계에 없는 판단은 합리적으로 정하고 구현 계획의 "검증 기록"에 근거를 남긴다. 범위가 크게 넓어지는 일은 먼저 묻는다.
- 커밋은 기능 브랜치에 작업 단위로 한다. 푸시와 병합은 사용자가 요청할 때만 한다.

## 6. 하지 않을 것

- 캐릭터 메이킹(단계 2), 7월 이후 일정·캠프·부상·경기 결과 보상(단계 3), 진급(단계 4).
- 연애 관련 기능, 희귀도·중복 돌파, 효과음.
- 다른 브랜치나 세션의 변경을 덮어쓰거나 되돌리는 일.

## 7. 완료 기준

- `npm test`, `npm run typecheck`, `npm run build`가 통과한다.
- 실제 규칙으로 16주를 시뮬레이션해서 혼합 방침의 6월 선발 점수가 65 이상(목표 68~69)인지 확인한다.
- 브라우저로 타자·투수 각각 3~6월을 진행한다. 새 훈련 메뉴, 숨김 능력과 꼬리표, 로그 패널, 훈련·사건 주사위, 새 메인 화면, 달력, 선택 팝업을 확인하고 디자인 시안과 비교한다. 모바일 폭, 키보드, 새로고침도 확인한다.
- 기본 카드팩 왕복과 옛 규격 카드팩 변환을 확인한다.
- 저장 버전, README, 스탯 개편 문서의 현재 수치, 구현 계획 체크박스와 검증 기록, `package.json` 버전을 갱신한다.
- 완료 보고에는 다음을 구분해서 적는다.
  - 바꾼 것
  - 검증한 것(실제 명령 결과와 측정값)
  - 남은 제한
  - 검증하지 못한 범위
