# 2차 개발 — 서포트 육성과 4월 출전 경쟁

사용자가 월별 편성 규칙을 확인하고 2차 개발 시작을 요청했다. 기존 시안과 선택형 경기, 평일/주말 구분을 유지한다. executing-plans 흐름으로 직접 구현하고 마지막에 별도 리뷰한다.

## 구현 범위와 결정

1. 3~4월 8주. 신규 선수는 3월 편성부터 시작한다. 매월 첫 활동 전까지 6명 중 3명을 편성/수정할 수 있고 활동 비용은 없다. 첫 활동 후 월말까지 고정한다.
2. 인물별 훈련 배치는 주차·인물·고정 시드에 의해 결정한다. 같은 주에 편성을 바꾸거나 재개해도 같은 인물의 배치가 바뀌지 않는다.
3. 함께한 활동으로 인연을 높이고, 인연 40 이상이면 합동 훈련 추가 성장. 인연 35 도달 시 1회 개인 사건을 제공하고 스킬 힌트를 준다. 연애 전용 수치·장면은 만들지 않는다.
4. 타격 선배/투수 선배/라이벌/포수/매니저/반 친구의 다른 강점, 8종 역할별/공통 스킬. 훈련·경기 SP를 사용하며 힌트는 비용을 낮춘다. 경기 중 구입은 금지한다.
5. 3월 연습경기 기록을 보존. 4월 4주 첫 공식전 직전에 능력·최근 개인 성적·감독 신뢰로 출전 평가. 타자는 선발/대타/대기, 투수는 선발/구원/대기. 부족한 점과 기준을 공개한다. 대기 선수는 동료 경기를 보고 주말로 진행한다.
6. 상태창에 서포트, 스킬, 출전 평가, 월별 변화와 경기 기록. 결산 화면을 추가하지 않는다.
7. 저장 v2. 구형 v1 저장은 원래 데이터와 처리 위치를 검증한 뒤 변환한다. 첫 달 완료 저장은 기존 성장·기록을 보존해 4월 편성부터 재개한다. 원본 키를 유지하며 최초 변환 저장 시 v1 백업을 남긴다.

## 실행 기록

- Ruling: 사용자 승인된 대화 내용을 구현 계약으로 구체화하고 재승인 없이 진행한다. 기간은 앞서 제안한 4월까지, 서포트 6명/3명으로 정했다.
- Ruling: 첫 커밋 없는 저장소에서 기존 파일을 보존하며 작업한다. 커밋·병합·공개 배포는 이번 범위가 아니다.
- 시작: 기존 v1 타자/투수의 시작·경기 결과·완료 상태를 fixture로 보존했다.

- 완료: 월별 편성과 8주 진행, 6명 서포트/8종 스킬, 실제 선발·교체·대기 출전, 월별 상태창과 v1 변환을 구현했다.
- 리뷰 수정: 같은 활동에서 개인 사건 조건을 함께 채운 모든 인물을 차례대로 처리한다. 활동의 원래 주력 성장 항목을 고정해 편성 순서가 보상을 바꾸지 않게 했다. 대타는 7회 이후 첫 팀 타석에 출전하여 타순이 돌아오지 않아 기회가 사라지는 문제를 해결했다.
- 검증: 회귀 테스트를 먼저 실패시킨 뒤 수정했다. 최종 `npm test` 44/44, `npm run build` (TypeScript 포함) 성공. 별도 리뷰어가 위 세 재현 경로를 다시 검사하여 모두 해결을 확인했다.
- 브라우저: 신규 타자 3~4월 완주, 구형 투수 3월 완료 저장에서 4월 편성·스킬 습득·공식전·마지막 주말 완주. 월별 교체, 사건 중 재개, 할인 구매, 합동 훈련, 경기 적용 스킬, 두 경기 기록·4월 성장 합계, 모바일 및 Enter/Escape 조작을 확인했다. error/warn 0건.
- 인계: 4173 미리보기의 기존 사용자 저장은 원문을 덮어쓰지 않고 읽어 4월 편성 화면에 열었다. 사용자가 다음 행동을 확정하면 v1 원본 백업 후 v2로 저장된다.
- 범위: 연애와 5월 이후, 상세 경쟁 선수·부상·시험·졸업·원화·음악은 후속으로 남겼다. 장기 육성의 재미와 수치 균형은 실제 플레이 피드백이 필요하다.
