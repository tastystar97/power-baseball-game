# 5차 개발 실행 기록

사용자의 “개발 시작해”에 따라 회의 기록의 추천안을 초기 구현 기준으로 적용한다. 추가 승인 단계 대신 필요한 세부 판단을 이 문서에 남기며 끝까지 구현·검증한다.

## 작업 순서

- [x] 1. v4 규칙과 저장 검증을 고정하고 실제 중간 저장 fixture를 확보한다.
- [x] 2. 전반/후반/주말 슬롯, 카드 사건 18개, 7종 주말과 지능 활동을 구현한다.
- [x] 3. 지능별 스킬 판정·정확한 평균 전망·수동/요약 발동 기록을 연결한다.
- [x] 4. v5 저장 이관과 구조·진행·중복 검증을 연결한다.
- [x] 5. 기존 UI에 반차 활동·인카운터·지능·스킬 발동을 표시한다.
- [x] 6. 역할별 전체 시즌, 모든 단계 저장 재개, 구형 저장, 브라우저와 독립 리뷰 후 문서를 갱신한다.

## 초기 구현 기준과 판단

- Ruling: 사용자가 기획 확인 뒤 개발을 직접 요청했으므로 상세 계획의 추가 승인 질문 없이 진행한다. 현재 서버·사용자 저장을 유지하기 위해 같은 작업 폴더의 기능 브랜치에서 구현한다. GitHub 재업로드는 이번 작업에 포함하지 않는다.
- 전반→인카운터(최대1)→후반→경기→주말. 3~6월과 월초 편성 유지. 동행 배치는 반차별 결정적 추첨. 신규 고정 야구부 사건 없음.
- 사건은 전반 이후 75% 추첨, 두 번 연속 미발생 시 다음에는 발생. 편성 인물의 일상2개/성장1개(인연35 이상, 1회성) 중 직전 사건을 제외하고 뽑는다. 결과를 선택 전 저장한다.
- 지능은 0~100, 시작45. 조건에 맞는 각 경기 스킬은 타석당 `0.5 + intelligence*0.004`로 독립 발동. 소유 선행 조건과 발동 조건은 분리한다. 요약도 동일하고 미리 보기는 난수를 소비하지 않는다.
- 스킬은 확률화에 맞춰 주요 발동 효과를 약1.4배 높인다. 기존 진행 중 경기만 기존 상시 효과를 끝까지 유지하며 새 경기부터 발동형을 사용한다.
- 구형 소비된 평일은 전반/후반을 모두 소비한 것으로 표시한다. 이미 열린 사건은 기존 선택을 마친 뒤 남은 원래 일정으로 복귀한다. 과거 슬롯·사건·스킬 발동은 만들어 넣지 않는다.
- 학업→지능은 값과 변화량 합계를 그대로 이관한다. 새 저장v5 최초 쓰기 전에 원래 버전별 백업을 남긴다. 사용자 저장은 QA에 사용하지 않는다.
- 기본 훈련·소모를 반차 크기로 줄이고 동행 인연은 회당8. 준서는 후반 종료 시 주간 기본 성장과 두 번의 공동 성장 기록을 한 번 반영한다.
