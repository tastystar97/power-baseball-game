# 개발 기록

## 4차 개발 — 주전 경쟁과 상대 고교 라이벌리, v0.4.0 (2026-09-30)

승인된 [4차 설계](superpowers/specs/2026-09-30-rivalries-design.md)와 [구현 계획](superpowers/plans/2026-09-30-rivalries.md)에 따라 직접 순차 구현하고 마지막 독립 리뷰를 진행했다.

### 구현과 결정

- 차준서는 편성 여부와 관계없이 평일 활동마다 한 번 성장한다. 함께 성공한 야구 활동은 주력 능력 추가 성장, 실패 시 기본 성장만 적용한다. 주간 기본/추가 수치를 합산한 뒤 성장 구간 배율을 한 번 적용하며 전술 공부는 안전한 야구 활동에 포함한다.
- 선발은 능력·준비도·감독 신뢰 비교로 결정한다. 준비도는 연습 평가와 최근 실제 출전 최대3경기 평균 중 높은 값이며 벤치 대기는 성적 평균에서 제외한다. 65점 이상 후보 중 높은 점수가 선발, 동점은 이전 선발 유지, 이전 후보가 없으면 플레이어에게 기회가 온다. 교체52점, 3월 체험 선발은 유지한다.
- 해솔고 에이스 정태오와4번 서지환을 실제 이닝·타순에 연결했다. 수동/요약 타석의 선택과 결과를 기록하되 난수·작전 확률은 추가로 변경하지 않는다. 팀 전적, 개인 맞대결, 미대결, 구형 세부 기록 없음을 구분한다.
- 현재/과거 명단과 점수 차이, 준서의 주별 성장, 학교 전적·설욕·재대결 대사, 개인 타석 기록을 편성·상태창·경기·완료 화면에 연결했다. 작은 화면에서도 경기 종료 후 개인 기록을 표시한다.
- 저장v4. 기존v3 검증기와 기본 생성값을 고정하고 실제v3 저장18개를 보존했다. 구형 확정 평가·진행 중 경기와 원래 수치·난수·기록은 유지한다. 과거 준서 공동 훈련/개인 타석/명단을 추측해서 만들지 않는다. 읽기만으로 저장하지 않으며 처음 새 저장 시 원래 버전별 백업을 보존한다.

### 리뷰와 최종 검증

- 독립 리뷰에서 홈런·희생번트가 집계되지만 화면 요약에서 빠지는 문제, 주말 개인 연습 뒤 평일의 준서 성장이 다시 표시되는 문제를 발견했다. 각각 회귀 검사가 실패하는 것을 확인한 뒤 공통 기록 문구와 평일 활동별 성장 연결로 수정했다. 주말에는 준서 성장 상태가 바뀌지 않는 것도 검사한다.

## 1차 개발 — 첫 달 시제품 (T1~T5)

사용자 요청: 2026-09-30 본격 개발 시작. 기존 작업 폴더의 문서·시안은 보존한다.

## 실행 결정

- Ruling: 이번 구현은 합의된 첫 달 T1~T5에 한정한다. 3년·졸업 T6~T8은 후속 계획이다. 범위를 오해했다면 후속 기간 확장이 필요하다.
- Ruling: 최신 UI 기획의 상태창과 자동 주차 이동을 따른다. 과거 결산 화면 계획은 적용하지 않는다. 비용은 화면 재설계가 아니라 상태창 검증으로 제한한다.
- Ruling: 첫 커밋이 없는 저장소라 작업트리 분리가 불가능하고 Git 메타데이터 쓰기가 제한되어 있다. 사용자 작업 폴더에 신규 앱 파일을 추가하며 기존 시안을 보존한다. 변경은 미커밋 상태로 검토 가능하다.
- Ruling: React·TypeScript·Vite를 선택하고 독립된 순수 규칙 함수와 Node 테스트를 사용한다. 테스트용 브라우저 자동화는 앱의 실행 의존성이 아니다.

## 계약

- `GameState`: 버전·역할·주차·단계·능력·생활 상태·관계·이력·경기·난수·revision을 직렬화한다.
- `transition(state, action)`: 기대 revision이 일치하는 유효한 행동만 적용한다. 중복 행동은 무시한다.
- 훈련·사건·경기의 실제 효과는 로그에 누적해 상태창에 표시한다.
- 경기 엔진은 이닝·주자·아웃·득점을 공통 처리하고 타자·투수의 작전 확률과 개인 기록을 구분한다.
- 저장은 구조와 진행 단계 일관성을 검증한다. 오류 시 기존 데이터를 자동 삭제하지 않는다.

## 작업 기록

- T1~T5: 시작. 테스트 → 규칙 구현 → UI 연결 → 브라우저 플레이 → 최종 검토 순서.

### T1~T5 구현·검증

- T1: 역할별 선수 생성, 이름 검증, 초기 능력/학교생활, 시안 기반 화면 구성 완료.
- T2: 평일 6/7종·주말 5종, 실제 효과 미리보기, 컨디션 보정, 자동 주차 이동 완료.
- T3: 주차 ID 1~3으로 고유 사건을 관리하며 역할별 효과·대사, 감독/라이벌/포수 관계, 반복 캐치볼을 연결.
- T4: 전체 타석 시뮬레이션, 역할별 작전 4개, 최대 3회 직접 승부, 부담·교체·잔루 책임, 개인 기록과 상태창 완료.
- T5: 저장 형식 및 진행 불변식 검증, 오류 안내, 모든 단계 재개, 새 게임 확인 완료.
- Ruling: 예정된 다수의 소규모 파일 대신 전이를 engine.ts, 경기 판정을 match.ts에 모았다. 4주 시제품에서 과도한 추상화를 줄였다. 규모 확장 시 파일 분리가 필요할 수 있다.
- Ruling: 첫 달 동료 캐치볼은 매주 가능하다. 부재 사건은 아직 없고 휴식·산책을 항상 제공한다. 이후 인물 일정이 생기면 조건 분기가 필요하다.
- Ruling: 주자 진루는 단타 1루/2루타 2루, 연장은 10회부터 2루 주자 배치로 단순화했다. 실책·병살·도루는 후속 범위이며 실제 야구의 모든 기록 규정을 재현하지 않는다.

### 발견·수정

- 개발 서버 의존성 최적화가 샌드박스의 상위 디렉터리 읽기 제한에 걸렸다. 허용된 실행 환경에서 서버를 재시작하여 해결했다. 빌드 자체는 성공한다.
- 상태창의 StrictMode effect 정리에서 열린 dialog가 배경 포커스를 막았다. 닫은 뒤 원래 버튼으로 포커스를 돌리도록 수정. Escape 후 activeElement가 상태창 버튼임을 브라우저에서 확인.
- Final review: 별도 검토 에이전트가 전체 소스를 읽고 두 역할 각 300개 시드, 총 600회 정상 진행과 중간 저장 왕복을 확인했다. 수정 전 정상 경로에서는 정지가 없었다.
- Final: fixed 완료 사건의 선택 대기/이미 소비한 활동 슬롯/교체된 투수 선택 대기를 저장 검증에서 거부. 재현 테스트 실패 후 수정, 전체 28/28 통과.
- Final: Ruling: '나'의 고정 위치는 실제 선수 상태를 잘못 전달하므로 이번 수정에 포함했다. 타자 출루 식별자를 보존하고 투수의 공격/교체/경기 종료 상태에 따라 표시한다. 비용은 주자 식별 해석이며 홈팀 타자와 원정팀 책임 투수로 구분한다.
- Final: fixed 본인 출루 식별 회귀 테스트 실패 후 수정. 브라우저에서 볼넷 후 1루의 '나', 투수 경기 종료 후 마운드 표시가 사라짐을 확인.
- 최종 경계 검사에서 능력 0/100 조합의 작전 가중치 합계가 1을 넘는 사례 발견. 표시와 추첨이 같은 정규화 확률을 사용하도록 수정. 재현 테스트 실패 후 통과.
- Final: Ruling: 3년·졸업·원화·애니메이션에 대한 리뷰 판단은 현재 범위 밖으로 유지한다. 첫 달 플레이 후 확장 여부를 결정하며 장기 반복 재미는 아직 검증하지 않았다.

### 브라우저 플레이 근거

- 타자: 타격·웨이트·휴식, 고유 사건 3개, 캐치볼, 개인 연습 목표 변경, 경기 3타석 선택, 마지막 주말 및 완료.
- 타자 경기: 2:3 패배, 개인 4타수 0안타 1볼넷 3삼진. 요약된 추가 타석도 성적에 반영됨을 확인.
- 투수: 구속·제구·변화구·지구력 훈련, 주말 휴식, 직구/변화구/유인구 선택, 마지막 캐치볼 및 완료. 모바일 크기에서 키보드 Enter/Escape 입력 사용.
- 투수 경기: 팀 2:8 패배, 본인 2이닝·2탈삼진·4피안타·1실점, 부담 64로 교체. 팀 실점을 개인 성적과 분리함을 확인.
- 사건 선택 결과, 타격·투구 결과, 주말 대화 선택 전 각각 새로고침하여 보상/주자/역할/처리 위치 유지 확인.
- 상태창 능력·기간별 변화·기록·관계·일지, Escape 포커스 복귀, 새 게임 확인 취소 확인.
- 좁은 화면에서 가로 넘침 없음. 정상 플레이 중 브라우저 error/warn 로그 0건.
- 실제 브라우저 저장소 차단/용량 부족은 주입하지 않았다. 이 경로는 저장 함수 실패 테스트로 검증했다.

### 자동 검증

- npm test: 28개 통과. 양 역할 × 훈련/균형/학업 패턴에서 모든 단계 저장 왕복과 로그 합계 일치 검증 포함.
- npm run build: TypeScript 검사 및 Vite 프로덕션 빌드 성공(종료 코드 0). JS 369.52 kB / gzip 114.46 kB, CSS 20.51 kB / gzip 5.17 kB. Zod 내부 주석의 PURE 표기 경고 2건이 있으나 빌드 오류는 없다.
- Git: 기존 첫 커밋이 없고 메타데이터 쓰기가 제한되어 커밋·병합·푸시는 수행하지 않았다. 원본 시안과 새 코드, 문서를 작업 폴더에 보존한다.



## 2차 개발 — 서포트 육성과 4월 출전 경쟁 (2026-09-30)

사용자가 월별 편성에 동의하고 2차 개발 시작을 요청했다. [구현 계획](superpowers/plans/2026-09-30-second-development.md)에 범위와 실행 상태를 기록했다.

### 구현과 결정
