# 마지막 여름 (가제)

야구 선수 한 명의 고교생활을 만들어가는 선택형 육성 웹게임입니다. 프린세스 메이커의 일정 관리와 파워프로야구의 선수 육성에서 영감을 받았으며, 인물·학교·대사·화면은 이 프로젝트의 콘텐츠로 구성합니다.

## 현재 플레이 범위

**v0.4.0 — 1학년 3~6월, 총 16주와 첫 여름 대회를 플레이할 수 있습니다.** 기존 [UI 시안](prototypes/ui-screens/index.html)의 색상·배치·그림 자리를 유지하며, 차준서와의 선발 경쟁과 해솔고와 쌓아가는 라이벌 관계를 연결했습니다.

- 이름과 **타자 / 투수**를 선택해 시작합니다. 매주 평일 활동 1회와 별도 주말 활동 1회를 고릅니다.
- **서포트 6명 중 3명**을 매월 편성합니다. 월초 첫 활동 전까지 수정할 수 있고, 첫 활동부터 월말까지 고정됩니다. 편성은 활동을 소비하지 않습니다.
- 활동 카드에서 이번 주 동행 인물과 실제 성장량을 확인합니다. 함께하면 인연 +15, 훈련 전 인연에 따라 파트너당 주력 능력 +1~+5가 추가됩니다. 인연 20마다 1씩 늘고 여러 명은 합산합니다. 인연 40 이상의 합동 보너스도 유지하며, 카드·확인 영역·일지에 실제 보너스를 표시합니다. 편성 수정·새로고침으로 같은 주의 인물 배치를 다시 뽑을 수 없습니다.
- 실전 훈련과 주말 개인 연습은 **시작 체력이 낮으면 실패**할 수 있습니다. 체력 70 이상 0%, 50이면 15%, 30이면 40%, 10이면 80%이며 선택 전에 성공·실패 시 변화를 보여줍니다. 성공 성장량·소모·회복량을 높였고, 실패하면 성장과 스킬 포인트 없이 추가 체력·스트레스·멘탈 손해를 받습니다. [현재 수치와 판정 규칙](docs/superpowers/specs/2026-09-30-training-risk.md)을 참고하세요.
- 함께한 활동 후 인연 35 이상인 인물은 1회 개인 사건과 스킬 힌트를 줍니다. 동시에 여러 명이 조건을 채우면 모두 순서대로 진행합니다. 교체한 인물의 인연·사건 이력도 남습니다.
- 기존 8종에 역할별 특화 2종씩을 더해 **총 12종 스킬**을 제공합니다. 능력과 선행 스킬 조건을 채우면 특화 스킬을 배울 수 있습니다. 교타·장타 또는 구위·제구 방향을 자유롭게 섞어 키울 수 있습니다. 훈련·경기로 모은 포인트를 쓰고, 힌트가 있으면 비용이 4 Pt 줄어듭니다. 습득 스킬은 실제 경기 확률과 판단 이유에 반영됩니다.
- **3월 연습경기 → 4월 공식전 → 5월 준비 경기 → 6월 8강·4강·결승**을 진행합니다. 가상의 8개 학교 대진과 실제 경기 결과가 연결되며, 탈락해도 남은 훈련·주말과 다른 학교의 대회 진행은 이어집니다. 경기 뒤 일요일 활동은 항상 남습니다.
- 상대의 구위·제구·장타·선구 특성과 대응 작전을 미리 보고 준비할 수 있으며, 실제 수동·요약 경기 확률에 적용됩니다.
- 능력 60부터 훈련 성장이 완만해집니다. 60~79는 75%, 80~89는 50%, 90 이상은 25%이며 스트레스·인연·100 상한을 반영한 실제 성장량을 카드에서 보여줍니다.
- **차준서와 선발을 경쟁합니다.** 준서는 편성 여부와 관계없이 매주 성장하고, 함께 성공한 평일 야구 훈련에는 추가 성장을 얻습니다. 능력·준비도·감독 신뢰를 비교하여 65점 이상 후보 중 높은 점수가 선발입니다. 동점은 직전 선발을 유지하며 이전 선발이 없으면 플레이어에게 기회가 옵니다. 준비도는 연습 평가와 최근 실제 출전 최대 3경기 평균 중 높은 값을 사용하므로 훈련으로 다시 따라잡을 수 있습니다. 3월은 신입생의 선발 체험 경기입니다.
- 선발이 아니어도 52점 이상이면 타자는 7회 이후 대타, 투수는 구원으로 출전합니다. 기준 미달은 벤치에서 관찰합니다. 상태창에서 두 후보의 능력·점수·차이, 준서의 매주 성장과 과거 명단을 확인할 수 있습니다.
- **해솔고와 실제 승부를 쌓으며 라이벌이 됩니다.** 3월·4월·여름 8강의 전적과 직전 승패가 재대결 대사에 반영됩니다. 타자는 에이스 정태오, 투수는 4번 타자 서지환과 실제로 만난 타석만 기록합니다. 직접 선택과 요약 진행을 모두 포함하며 안타·홈런·볼넷·삼진·희생번트, 팀 전적과 개인 결과를 구분합니다.
- 경기는 중요 승부 최대 3회(대타 1회)를 직접 선택하고, 나머지 타석은 시뮬레이션합니다. 투구 부담과 교체, 남긴 주자의 실점 책임도 반영합니다.
- **상태창**에서 능력, 스킬, 이번 주/이번 달/입학 이후 변화, 누적·경기별 기록, 시즌 대진과 상대, 모든 서포트와의 인연, 활동 일지를 확인합니다. 주간·월말 결산 화면은 없습니다.
- 행동마다 자동 저장하며 사건·경기·편성 단계에서 이어서 할 수 있습니다. v1 첫 달 완료 저장은 4월, v2 4월 완료 저장은 5월 편성으로 이어집니다. 진행 중인 사건·경기도 그대로 재개합니다.

**흐름:** 월초 편성 → 평일 활동 → 조건을 채운 인물 사건 → 야구부 사건 또는 경기 → 주말 활동 → 다음 주. 월말 마지막 주말 뒤 다음 달 편성, 6월 마지막 주말 뒤 대회 결과·성장 방향·누적 기록을 보여주는 시즌 완료 화면으로 이어집니다.

미연시는 보류했습니다. 반 친구·학생 매니저는 야구 육성을 돕는 서포트로 등장하며 연애 전용 수치나 장면은 없습니다. 7월 이후·3년 진행·졸업 진로·시험·부상 사건·원화·음악은 아직 구현하지 않았습니다.

## 실행

Node.js **22.18 이상**이 필요합니다. 개발·검증에는 Node.js 24.20.0과 npm 11.19.0을 사용했습니다.

```powershell
npm ci
npm run dev
```

터미널에 표시되는 주소를 엽니다. 기본 주소는 `http://127.0.0.1:5173`입니다. HTML 파일을 직접 열면 앱이 실행되지 않습니다.

```powershell
npm test          # 육성·일정·경기·저장 규칙 검사
npm run typecheck # TypeScript 검사
npm run build     # 타입 검사 후 dist에 배포용 빌드
npm run preview   # 빌드 결과 확인: 기본 4173 포트
```

## 저장

저장 형식은 **v4**이며 기존 호환성을 위해 저장 키 `last-summer.save.v1`을 유지합니다. 현재 브라우저와 사이트 주소별로 저장 1개를 유지합니다. 개발 서버와 미리보기 서버는 포트가 달라 저장도 서로 다릅니다.

- 이름·역할·능력·월/주차·진행 단계·편성·인연·스킬·일지·누적 경기·난수 상태를 함께 저장합니다.
- v1/v2/v3는 원래 형식으로 검증 후 변환합니다. 불러오기만으로 원문을 덮어쓰지 않으며, 처음 v4를 저장할 때 원본을 각각 `last-summer.backup.v1` / `last-summer.backup.v2` / `last-summer.backup.v3`에 보관합니다. 백업 실패 시 이전 저장도 덮어쓰지 않습니다.
- 이미 확정된 구형 출전 평가와 진행 중 경기는 그대로 유지하고 다음 평가부터 경쟁 규칙을 적용합니다. 준서는 지난 기간의 기본 성장만 복원합니다. 구형 경기의 개인 맞대결은 ‘세부 기록 없음’으로 표시하며 과거 타석이나 명단을 만들어 넣지 않습니다. v3 시즌 완료 저장은 완료 상태를 유지합니다.
- 손상된 데이터나 지원하지 않는 버전은 오류를 표시하고 기존 원문을 자동 삭제하지 않습니다.
- 저장소 접근/용량 오류가 발생해도 현재 창에서는 플레이를 이어갈 수 있습니다. 이때 저장되지 않는다는 안내를 표시합니다.
- 새 선수로 바꿀 때 확인하며, 새 선수의 **입학하기**를 누르는 시점에 이전 저장을 덮어씁니다.
- 서버 동기화·계정·클라우드 백업은 없습니다. 브라우저 데이터를 삭제하면 저장도 사라집니다.

## 구현 구조

React 19 · TypeScript 5.9 · Vite 7 · Zod 4를 사용합니다. 설치 버전은 `package-lock.json`에 고정되어 있습니다. 조작과 텍스트는 DOM, 야구장과 임시 인물은 SVG로 표현합니다.

```text
src/
  game/          # 직렬화 가능한 상태, 순수 상태 전이, 난수, 경기 규칙과 테스트
  content/       # 역할별 활동, 인물, 스킬, 사건, 그림 슬롯
  persistence/   # 저장 검증·재개와 테스트
  ui/            # 편성·육성·경기·상태창·공통 UI
  App.tsx        # 시작·선수 생성·활동·사건 화면 연결
  main.tsx
  styles.css     # 기존 UI 시안의 스타일과 반응형 보완
prototypes/      # 기존 시안 보존. 게임 상태와는 별개
```

게임 규칙은 화면과 분리했으며, `transition(state, action)`은 현재 revision과 일치하는 유효한 행동만 처리합니다. 동일한 초기 상태·난수 시드·행동은 동일한 결과를 만듭니다.

그림은 현재 시안의 패턴 배경과 실루엣을 사용합니다. [에셋 정의](src/content/assets.ts)의 `src`에 사용 권한이 있는 이미지 경로를 연결하면 교체할 수 있습니다. 배경은 16:9, 인물은 3:4를 기준으로 하며, 이미지 로드에 실패하면 임시 그림으로 돌아갑니다.

## 검증과 현재 한계

- 자동 테스트 **90개**: 기존 육성·경기·대회 검사에 경쟁자 성장·동점 선발·실제 맞대결·학교 관계·v4 검증과 v1/v2/v3 이관을 추가했습니다. v3 실제 저장 18개와 진행 중 16개 저장의 시즌 완료를 검사합니다.
- 타자·투수 × 훈련/균형/학업 × 20개 시드, 총 120시즌의 모든 단계 저장 왕복과 성장 로그를 검사합니다. 맞대결 추적 유무를 비교한 48경기에서 난수와 경기 결과가 같았습니다.
- 3~4월 학업 후 5월부터 훈련으로 전환한 20개 시드에서 타자 12개·투수 11개가 준서에게서 선발을 가져왔습니다. 일정한 훈련 위주는 선발 유지, 학업 위주는 교체 출전 경향이 있으며 수치는 초기 밸런스입니다.
- 브라우저에서 두 역할의 16주, 세 차례 해솔고전, 선발 복귀와 실제 맞대결 기록, 저장 재개, 모바일 390px·키보드를 검사했습니다. 독립 리뷰에서 발견한 홈런·희생번트 요약 누락과 주말의 준서 성장 중복 표시를 수정했습니다. 상세 근거는 [개발 기록](docs/development-log.md)에 남겼습니다.
- 규칙 검증은 재미와 밸런스 검증을 대신하지 않습니다. 경기 확률과 활동 수치는 플레이 피드백에 따라 조정할 초기값입니다.
- 경기의 단타는 1루, 2루타는 2루씩 진루하는 간소화 규칙입니다. 실책·병살·도루·수비 위치별 플레이는 아직 없습니다. 동점이면 10회부터 2루 주자를 놓고 연장합니다.
- 경쟁자는 차준서 한 명이며 공식전 개인 성적을 별도로 시뮬레이션하지 않습니다. 전체 선수단·세부 수비 포지션 경쟁은 없습니다. 학업의 시험·진로 효과와 장기 관계 분기는 후속 범위입니다.
